# AWS KMS 变更核对指南

面向使用 Terraform 管理 KMS 授权的平台与云安全团队。通过两份可直接使用的工作表，分别核对批准的变更、云端配置、应用行为与交接证据。

## 先完成一个具体任务

- 撤回 Grant 后准备签收：[授权与撤回核对表](guides/kms-change-checklist.md)。
- apply 中断，准备判断恢复路径：[中断变更证据表](guides/interrupted-change-worksheet.md)。

表格可以配合你已有的工具使用，无需安装软件或提供云权限。填写后的资料保存在自己的环境。这里不提供可直接执行的恢复命令。

## 怎样使用

1. 挑选一次已批准的非生产变更，明确资源、操作和观察窗口。
2. 在内部工作表中填入证据位置，由另一位工程师复核。
3. 将“已确认”和“尚未知”分开交接，避免把请求成功当成整个任务完成。

你可以公开提交文档纠错或不涉及内部数据的概念问题。请勿提交 Terraform state、计划、凭证、云日志及客户标识。

| 功能 | 交付与验收 |
| --- | --- |
| Terraform 密钥、角色与权限治理 | 计划绑定审批、职责隔离、独立读回、完整撤权及有界恢复；新建资源和存量工作区使用不同入口。 |
| 管理接口与业务原生 SDK | 应用直接调用 AWS KMS；对固定参考应用核验治理前后行为，客户原应用兼容另验。 |
